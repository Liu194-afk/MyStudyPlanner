Ethics & Privacy

Even a small study app stores personal information, such as which courses I take and which deadlines I am worried about. This page explains how the actual code of MyStudyPlanner tries to handle that data in an ethical and privacy-friendly way.

Features that support ethical data use

Only collecting what is needed

The task form only asks for six things: title, course code, course name, due date, description and notes. It does not ask for a real name, email, student ID or location. If the app never collects a piece of data, it cannot misuse it or lose it.

Clear validation instead of silent behaviour

Every input is checked before it is saved. Required fields cannot be empty, the course code must look like a real course code (for example INFO1012), and a due date that is not a real date or is already in the past is rejected with a message like "Due date cannot be in the past." The app never pretends to save something it actually refused.

Dangerous actions need confirmation

Deleting a task cannot be undone, so the app always asks first. The confirmation dialog names the exact task, for example "Delete 'Assignment 3' (INFO1012)?", and the safe option (Keep task) is focused by default, so it is harder to delete something by accident.

Features that support data privacy

Data stays in the browser

Tasks are saved in the browser's localStorage under a key for the logged-in user (msp-tasks-student). The site makes no network requests at all - there is no server, no database and no third-party script, so the task list never leaves the user's own device.

Login restriction with a short session

The task workspace is hidden until the user logs in. The login state is stored in sessionStorage, which the browser deletes when the tab is closed. On a shared computer, for example in a university lab, closing the tab is enough to keep the next person out of the workspace.

No tracking

The site only loads its own files: one stylesheet, three JavaScript files and a few images I drew myself. There are no cookies, no analytics, no advertising scripts and no external fonts, so no third party can see when or how the site is used.

Honest limitations

Two limits are worth stating. First, localStorage is not encrypted, so anyone with physical access to the same computer and browser profile could read it - that is one more reason the app avoids collecting sensitive details. Second, the login uses a hard-coded demo account (student / info1012) because this is a course assignment; a real product would check passwords on a server and store them as hashes, not as plain text in the JavaScript file.
